# 第 1 章　产品概述

## 1.1 产品定位与背景

**AI 问书** 是一款面向出版机构的「把纸书变成可对话 AI」的知识变现产品。读者扫描书籍封底二维码（或打开分享链接）即可进入该书专属的 AI 会话，用自然语言提问，由系统基于该书知识库检索后给出**带多模态素材与章节溯源**的回答；机构（出版社）在后台把书籍加工为知识产品（KP）、配置 Agent 人设与定价权益、生成二维码并查看经营数据；平台超管统一管理机构、账户、大模型与全局策略。

产品的商业闭环是：**机构把内容资产 KP 化 → 通过二维码触达读者 → 读者在问答中触发付费墙（会员订阅 / 永享买断 / 兑换码）→ 资金进入机构账户**。平台以多租户 SaaS 形态为机构提供能力底座与大模型用量。

## 1.2 目标用户与角色

系统区分**三端使用者**与前台的**四种 C 端权益角色**。三端使用者决定「能进入哪个后台 / 前台」，C 端权益角色决定「能看到哪些受限内容」。AI 问书前台不提供游客 / 匿名浏览态——读者须先登录授权方可使用。

| **类别** | **角色** | **说明** |
|-|-|-|
| 三端使用者 | **C 端读者** | 出版物的真实读者，主要从扫码进入前台 H5；登录授权后可提问、付费、回看历史。 |
| 三端使用者 | **机构运营** | 出版社的编辑 / 运营 / 客服 / 财务，登录机构后台，按角色权限操作 KP、Agent、定价、看板等。 |
| 三端使用者 | **平台超管** | 平台运营方，登录平台超管后台，管理机构、账户、角色、大模型与全局策略。 |
| C 端权益角色 | **免费用户** | 已登录、无任何付费权益；仅可查看「免费」内容。 |
| C 端权益角色 | **AI 会员** | 拥有有效会员权益；可查看「免费」+「会员」内容；「永享」内容仍需另行按 KP 买断。 |
| C 端权益角色 | **免费 + 永享** | 无会员，但对某些 KP 拥有永享买断；可查看「免费」+ 已买断 KP 的「永享」内容；「会员」内容仍需开通会员。 |
| C 端权益角色 | **会员 + 永享** | 同时拥有会员与永享；可查看「免费」+「会员」+ 已买断 KP 的「永享」内容。 |

## 1.3 核心价值与产品形态

- **对读者：**把「读书时的疑问」即时变成「可追问的对话」，回答带原文出处（书名 / 章节 / 页码）与图音视频素材，可信、可深入；会员可用实时电话式语音问答。
- **对机构：**零代码把已有书稿、音视频转成可问答、可变现的知识产品；二维码即渠道，后台看板量化经营，知识再运营，增加新商业化途径。
- **对平台：**多租户统一管控机构、账户与大模型用量，支持上下级机构结构与跨机构内容分享。

三端入口与视口：机构前台 H5（移动端，扫码 / 链接进入）、机构后台 PC（桌面）、平台超管 PC（桌面）。视觉采用方向 B：奶白底 + 电光靛 + 朝霞橙。

## 1.4 名词术语表

| **术语** | **含义** |
|-|-|
| **KP（知识产品 Knowledge Product）** | 机构把一本书 / 一个系列 / 一位专家 / 一个领域加工成的可问答内容单元，是内容与定价、二维码、Agent 绑定的载体。 |
| **Agent（人设）** | KP 背后的 AI 形象：头像 / 形象图 / 声音（TTS）/ 人设风格（原「回答 Prompt」，0812 更名，七档平台预设 + 自定义）；机构 Agent 全机构唯一并由平台初始化，普通 Agent 可自由创建。 |
| **永享（买断）** | 对单条受限媒体内容的永久解锁权益，按 KP 维度授予，跨 KP 不通用。 |
| **会员** | AI 会员订阅，按月计费、自动续费；可查看全部「会员」内容。**「0807 修订」会员状态四态**（任一时刻互斥）：有效会员（权益生效中，含连续包月期内）/ 宽限期（待续费）（权益已到期、处于续费宽限窗口，权益暂保留并引导续费）/ 会员已过期（权益终止且已出宽限窗口）/ 未开通会员（从未开通）；判定与到期时间由后端下发。 |
| **二维码包** | 机构一次创建生成的一批二维码（首扫绑定模式可生成 N 个），印刷于书籍封底等位置，扫描进入对应 KP 的会话。 |
| **上级机构** | 机构所属的父级机构（如集团与分社的关系，对应数据中的父级 ID 自引用）；仅允许一层。上级机构账户可汇总查看并下钻关联机构数据。 |
| **切片（Slice）** | 知识文件解析后用于向量检索的内容片段（按章节 / 语义 / 字数切分）。 |
| **付费墙（Paywall）** | 读者触碰受限内容时弹出的购买引导（会员 / 永享 / 兑换码）。 |
| **溯源** | 回答下方「参考 N 篇知识」，展示命中的知识 KP（含页码 / 时间戳）与互联网检索来源。 |

## 2.3 权限与多租户原则

- **机构数据强隔离：**所有业务数据按机构归属，机构之间默认不可见；切换机构即切换全部上下文（KP / 用户 / 订单 / 客服信息 / 品牌色等）。
- **前台权益判定：**以 C 端角色与永享授权判定受限内容可见性（详见第 4 章业务规则）。
- **后台 RBAC：**机构账户绑定角色，角色挂载权限点；「人设风格-自定义」（0812 由「Agent 回答 Prompt 编辑」更名）等敏感权限默认不勾选，由平台超管对内置角色统一开关。
- **上级机构：**仅一层；上级机构账户登录后仅见「主控台」，对关联机构汇总 + 只读下钻，隐藏账户管理 / 系统配置等敏感菜单。

## 3.1 关系说明

- 一个**机构**拥有多个**机构账户**，每个账户对应一种**角色 / 权限**；一个机构拥有多个**知识产品 KP** 与多个**读者用户**。

- 机构之间通过「上级机构」形成至多一层的上下级关系，并可通过 KP 跨机构分享共享内容。

微信内 / 外部浏览器 / 手机号三入口，最终汇聚到「是否已绑手机号」判定后进入会话。

**关键处理（评审重点）：**

- **H5 无法一键获取手机号**：微信「一键授权手机号」为小程序 getPhoneNumber 专属能力，H5 公众号网页不具备；故无论微信内 / 外部浏览器，手机号一律由用户手动「手机号 + 验证码」绑定。
- **手机号唯一性**：C 端用户手机号「机构内唯一、全平台可重复」——同一手机号可在不同机构各注册一个账户；绑定时若该号在本机构已被占用，直接提示「该手机号已被本机构其他账号绑定，请更换或联系客服」，**不做账号合并**（A、B 两个微信绑同一手机号亦同此提示）。
- **敏感操作门槛**：未绑手机号可用基础功能；支付下单 / 兑换码核销 / 开通·充值·续费会员前前置校验绑定，未绑则弹窗引导（可暂不绑定，但该操作需先绑）。

- **不要求全部开发完成：审核只要求填写的网站域名下有可访问的页面**、能体现真实业务场景（与经营类目一致的商品 / 价格 / 订单流程 / 支付按钮）；权限开通前技术上无法调起真实支付，支付按钮点击后给「支付暂未开通」提示即可。常见驳回原因是页面空壳（「无实际业务场景」），内容需做实（真实书目、真实价格）；驳回后可完善重提。
- \*\*域名与商户号主体：\*\*要求 ICP 备案主体与商户号主体一致；不一致需上传 **ICP 备案授权书**（域名备案主体盖章）+ 双方合作证明。**建议支付域名备案主体直接与商户号主体保持一致**，免去授权材料与审核风险。
- \*\*建议时序：\*\*① 先申请开通 JSAPI 支付（依赖认证服务号、门槛低）并开发微信内支付；② 同期在正式域名部署简易业务页、提交 H5 支付申请；③ H5 审核通过（7 个工作日内）后开发外部浏览器支付。
- **（0812）调价扣费口径「就低不就高」**：自动扣费价 = min(签约价, 当前售价)——降价按新价扣（扣费前须告知，并入续费提醒短信降价版）、涨价存量按签约价扣（「不高于」型模板天然支撑）、新用户按新价签约。
- **（0812）会员月度对日周期**：自开通当日顺延至次月同日；次月无对应日期则顺延至当月最后一日并固化（示例：1 月 31 日开通 → 当期至 2 月 28 日，此后每月 28 日续费）。扣费日＝到期日前 1 天。
- **（0812）续费提醒短信：扣费前 5 天发送**，签名固定【科技文献出版社】。**标准版**：「【科技文献出版社】您订购的AI问书会员将于${到期日}到期，${扣费日}我们将通过微信自动续费${金额}元。如需退订，请前往微信"我的-服务-钱包-支付设置-自动续费/免密支付"管理。」**降价版**（会员价下调时替换标准版，一并告知降价）：「【科技文献出版社】您订购的AI问书会员将于${到期日}到期。会员价已由${原价}元调整为${新价}元，${扣费日}我们将通过微信按新价格${新价}元自动续费。如需退订，请前往微信"我的-服务-钱包-支付设置-自动续费/免密支付"管理。」

**③-1（0812 定稿）H5 权限被拒预案：非微信浏览器改走 Native 扫码。**前提：不注册小程序（小程序支付中转方案不采用）。手机场景流程：识别非微信环境 → 生成支付二维码 → 用户下载 / 截图二维码 → 打开微信扫一扫、点击相册选择该二维码 → 完成支付。设计原则：**离开前不用想、离开时拿得走、回来时不用操作**。

- **二维码卡**：大尺寸二维码居中 + 金额与订单摘要就近展示（扫码前最后一次确认）+ 有效期提示「二维码 15 分钟内有效 · 过期可返回重新下单」（0812-e 定稿）——**全平台支付倒计时统一 15 分钟**：微信内 JSAPI 与非微信 Native 扫码同口径，二维码与订单同生共死（下单传 `time_expire`，码随单失效）；不做「重新生成」，码过期即订单已失效、需重新下单。
- **主按钮「保存二维码到相册」**：canvas → a[download] 触发下载；不展示「长按二维码保存 / 截图」兜底文案行（0812-b 定稿，减噪）。非微信分支不显示「浏览器支付 · 微信扫码（Native）」环境标签——二维码形态自解释（微信内 JSAPI 标签保留）。
- **三步引导**（紧贴二维码下方，图标 + 短句）：① 保存二维码 ②「微信扫一扫，点击相册」③ 选择二维码完成支付。
- **回流自动化**：页面持续轮询查单（商户查单接口），支付成功自动跳转成功页——用户从微信切回时零操作；辅以「我已完成支付」手动查单兜底 +「等待支付中」状态提示。
- **PC 浏览器**：同一 Native 分支直接扫屏即付，无需下载步骤；手机浏览器无法同机扫屏，故以「保存二维码 → 相册识别」为主路径。
- **Native 待支付订单详情内嵌扫码卡（0812-b）**：订单新增 payChannel（jsapi / native）；Native 下单的待支付单，C 端订单详情在倒计时条下方内嵌「扫码支付」卡（二维码 + 保存按钮 + 指引「微信扫一扫 · 点击相册选择二维码完成支付」+ 轮询等待与「我已完成支付」兜底），倒计时条不再放「去支付」；JSAPI 待支付单保持「去支付」回收银台。
- **为何不用「复制链接去微信打开」**：该路径需引导用户离开→粘贴→重新登录（或建免登 token 体系），步骤多且依赖用户操作准确性；Native 扫码是微信官方标准通道、无新增资质，扫码即支付且天然免登录。

**④ 自动续费＝委托代扣（扣费服务 · 预约扣费）。**

- \*\*流程：\*\*用户签约（授权关系）→ 每期扣款日前一天商户调「预约扣费」接口 → 微信 30 分钟内向用户发预扣费通知 → 商户调「受理扣款」完成扣款。代扣为受限能力，需在商户平台提交场景申请（业务介绍、扣费周期、金额、会员服务内容）。
- \*\*扣款日后移不影响签约：\*\*微信侧没有固定扣款日，每期扣款时点由商户发起预约决定；权益顺延导致扣款日推迟只是商户侧调度晚一期发起预约，签约协议不动，不存在「到期扣不出」问题。
- **系统需记录：**「下次扣款日」字段 + 变更历史（变更原因：兑换码顺延 / 退款收回 / 手动调整，关联来源单据）。
- \*\*签约模板金额申请「不高于」型：\*\*模板扣费金额类型分「为」（固定）与「不高于」（上限）。机构后台可调价 → 须申请「不高于」型模板、上限覆盖机构可调价区间；固定金额模板会因实际扣款与模板不符导致扣款失败 / 模板失效——这是申请时的关键决策。

**⑤ 会员权益分段记账（含兑换码冲突处理）。统一原则：每段会员时长记账，记录 {来源类型（购买 / 兑换码 / 赠送）、来源单据、起止时间、状态}；同类权益按时间顺延排队**；退款**按来源段收回**。

| 场景 | 处理 |
|-|-|
| 已是会员（购买）再兑换兑换码 | 兑换段接在当前到期日之后顺延生效 |
| 开通自动续费 + 兑换兑换码 | 兑换段顺延；下次扣款日推迟至全部权益段耗尽前（商户侧调度，见 ④，需记录变更） |
| 购买单全额退款、队列中还有兑换段 | 只收回该购买单对应的时间段；兑换段自动前移，自退款生效日起顶上 |
| 购买单部分退款 | 权益不收回（沿用现行规则） |
| 多张兑换码连续兑换 | 依次顺延排队 |
| 会员 × 永享 | 两池独立互不影响（既定规则）：会员是全库时限权益，永享是单 KP 永久权益 |
| 收回的段正在生效 | 会员立即降级到队列中下一段；无下一段则会员失效 |
| 收回的段尚未开始 | 直接从队列移除，后续段前移 |

**⑥ 短信到达率问题与缓解方案（后端 / 运营侧，原型不涉及）。短信链路为 供应商 → 三大运营商各省网关 → 手机：各省各运营商对签名 / 码号要求实名报备、进度参差，且部分运营商不回传结果——未报备通的地区会静默丢弃**短信，供应商与商户均看不到真实失败。这是行业通病（阿里云 / 腾讯云 / 华为云机制相同），换供应商不能根治。

- \*\*事前：\*\*签名 / 资质在各运营商报备做全，控制台核对报备状态。
- \*\*事中：\*\*监控发送回执，某地区 / 运营商失败率异常时主动提工单要求疏通，不等用户投诉。
- \*\*兜底：\*\*验证码等关键短信失败后自动切换备用通道——第二家供应商双通道灾备 + **语音验证码兜底**（行业标配，产品化交互见 4.4.4 / 6.1.1）。
- \*\*内容：\*\*避开营销敏感词，降低网关拦截概率。
- **语音为何不受地区不达影响：行业短信（106 端口号）必须过省级短信网关的报备 / 拦截体系；语音验证码本质是一通电话、走语音通话网，不经过短信网关——号码有效、手机开机即可呼达。语音自身失败模式是用户不接陌生来电 / 号码被标记骚扰，故定位为短信失败后的兜底**，不是全量替代。

**⑦ 支付参数配置面落地（「0807 新增」）。**上述对接所需参数在「平台后台 · 机构详情 · 机构配置 · 微信配置 · 微信支付卡片」按接入用途排列为八字段：商户号 MchID / API v3 密钥 / **API v2 密钥**（委托代扣签约·扣款接口仍走 v2 签名，配置连续包月必需）/ 商户证书 apiclient_cert.pem / 商户 API 私钥 apiclient_key.pem / **支付公钥 ID** + **支付公钥文件 pub_key.pem**（公钥模式验签，2024 年起新注册商户默认发放、替代平台证书；验签按回调头 Wechatpay-Serial 匹配）/ **委托代扣包月模板 ID**（签约模板审核通过后分配的 plan_id）。字段规格详见 6.3.2 机构详情 Tab 3。**（0812）微信公众号卡片新增「微信公众号名称」（必填，置公众号 AppID 之前）与「备注」（选填，0812-e 置卡片末位、域名校验文件之下）两字段，均为非敏感项、正常回显。**

- **微信登录环境分流**：按「打开环境」分两路——微信内 → 微信官方授权弹窗页；浏览器 → 微信扫码授权页。
- **演示环境切换区**（明确标注「仅用于演示 · 非上线功能」）：开关 A 微信内 / 浏览器（控制微信登录与支付通道）、开关 B 机构 Token 正常 / 超限（控制会话页是否出现超额提示条），供评审切换两条流程。

**▍ 微信授权登录（两种场景）**

微信网页授权（公众号网页授权 OAuth2），按打开环境分两种交互；H5 网页授权**只能拿回昵称 / 头像 / 性别 / 地区，拿不到手机号**（一键授权手机号是小程序专属能力）。

**规则与交互要点**

- **微信 App 内打开 → 官方授权弹窗**：模拟微信内置浏览器，点「微信授权登录」不出二维码、直接唤起官方授权 sheet（授权 昵称 / 头像 / 性别 / 地区）；允许 → 带回资料并跳手机号绑定页；拒绝 / 点遮罩 → 返回落地页。
- **外部浏览器打开 → 微信扫码授权页**：整页为 AI 问书自有页面（可美化），二维码由微信域名生成、**中央不放 AI 问书 Logo**（二维码属微信、避免误导）；三态自动演进：等待扫描 → 已扫描·待确认 → 已确认·登录中 → 跳手机号绑定页。
- 微信登录回调后置 phoneBound=false，引导绑定手机号；手机号验证码登录则视为已绑、不获取微信信息。

**▍ 手机号验证码登录**

手机号（11 位）+ 短信验证码（6 位）直接登录，登录成功即视为已绑手机号，**不获取 / 绑定任何微信信息**；「获取验证码」演示态即时提示已发送；号码 / 验证码格式即时校验，任一为空时登录按钮禁用。

**▍ 语音验证码兜底（覆盖登录 / 绑定 / 换绑）**　**「0724 新增」**

短信验证码未收到时的语音电话兜底获取入口，覆盖 C 端全部短信验证码场景（手机号登录、手机号绑定、换绑手机号），交互统一。

**规则与交互要点**

- 发送短信验证码后进入 60 秒倒计时；倒计时结束仍未输入 → 输入框下方出现次级入口「未收到短信验证码？接听语音电话获取」。
- 点击即拨打（不加确认弹窗，点击即同意），入口原地变为状态行「语音电话拨打中 · 来电以 95013 开头，请留意接听」——号码开头提示在点击瞬间原地出现并在等待期间常驻，避免用户当骚扰电话拒接。
- 拨打中状态行常驻「N 秒后可重拨」倒计时；归零后变为「未接到电话？再次拨打」，点击立即重拨（toast 反馈）并重启 60 秒，可循环重拨。
- 语音码与短信码同码同校验：提交时真实校验（原型演示码 123456，输入框下方常驻提示），输错 toast「验证码错误，请重新输入」并拦截，输对才放行——登录 / 绑定 / 换绑三处一致。
- 倒计时按截止时间戳计算剩余秒数，不逐秒递减——浏览器对后台标签页 / 锁屏会节流定时器，逐秒递减会在用户切去微信等验证码再切回时变慢数倍；监听 visibilitychange 切回即校准（短信重发、语音重拨、订单待支付倒计时同规则）。
- 频控要求（后端实现，原型不做交互）：语音重拨建议同一手机号单次验证流程连续重拨 ≤ 3 次、每日 ≤ 5 次，超限返回明确错误码，前端按返回提示「拨打次数已达上限，请稍后再试或联系客服」；短信发送按供应商频控（通常 1 条/分钟、每日上限）做服务端限流——防骚扰投诉（外呼号码被标记会拖垮整体接通率）、防刷接口费用。
- 「95013」为原型演示号段，实际外呼号段以短信 / 语音供应商分配为准，上线前替换文案。短信到达率背景与双通道灾备见 4.4.5。

**▍ 手机号绑定（可暂不绑定）**

统一「手机号 + 验证码」绑定页，一页复用三个来源、文案随来源变化（H5 拿不到手机号，故所有绑定都走短信验证码）。

**规则与交互要点**

- **来源差异**：微信登录后（login）副标「绑定后可跨端同步会话与权益」、底部有\*\*「暂不绑定 · 直接进入」\*\*可跳过先进会话；敏感操作门槛引导（gate）副标「支付下单、兑换码与开通会员需先完成绑定」；「我的」主动绑定（me）。
- 成功 → toast「手机号绑定成功」后按来源跳转（login 进会话 / gate·me 返回原页）。
- 底部固定入口「手机号已被占用?」→ 占用提示页。

**▍ 手机号已被占用（无账号合并）**

手机号在本机构已被他人占用（含 A、B 两个微信绑同一手机号）时的提示页。**账号合并逻辑已删除**——引导用户直接使用手机号登录，无法登录时联系客服人工核验；不顶替、不迁移权益。

**规则与交互要点**

- 文案：「手机号 138\*\*\*\*8888 已被占用。请更换其他手机号绑定，如有疑问请联系客服。」
- 操作：「更换手机号」（返回绑定页）/「联系客服」（弹客服弹窗）。**无合并按钮、无合并流程**。

**▍ 换绑手机号**

账户管理入口（仅已绑手机号时显示），显示当前号「138\*\*\*\*8888」，输入新手机号 + 验证码（同样 11 / 6 位校验）→ toast「换绑成功」返回。

**▍ 二维码失效落地页**

纸书 / 分享二维码**本身作废**时进入：大二维码灰图 +「二维码已失效」+「N 秒后自动跳转首页」（3 秒倒计时），到点自动跳首页，亦可「立即前往首页」。KP 已下架 / 已删除的扫码不走本页，改走 /kp/:kpId 判活入口（提示已下架 / 已失效并按跳转规则①处理）。

**▍ 登录前置（无游客态）**

AI 问书前台**不提供游客 / 匿名浏览**：从落地页须先完成微信授权或手机号登录方可进入会话。会话采用**滑动 7 天**：每次有效认证请求刷新最后活跃时间，连续 7 天无有效请求后失效；重新登录可恢复原目标地址，但不自动补发未认证输入。

**▍ 用户协议 / 隐私政策**

两个独立法律文档入口（用户协议 / 隐私政策），纯文本 / Markdown 渲染，底部带更新日期。

**规则与交互要点**

- **（0812）机构主体名称变量化**：《用户协议》《隐私政策》《会员服务协议》《自动续费（扣费）协议》内的机构主体名称取自平台机构详情 · 基本资料的「机构主体全称」（营业执照名称）字段，随机构配置注入、不写死。
- **用户协议关键条款**：服务说明（答案 AI 生成，请结合专业判断）；登录方式（微信 / 手机号）；**会员为订阅制，支持随时退订，到期赠 72 小时会员缓冲使用期；永享内容为一次性买断**；版权说明（图音视频仅在线预览、不支持保存下载）。
- **隐私政策**：收集范围（登录标识 / 提问记录 / 订单信息）、信息使用、信息共享、用户权利。

### 6.1.2 AI 会话

**▍ Agent 形象 sticky 区**

会话顶部固定 Agent 形象，会话区下滚渐隐隐藏、上滚复原显示。

**▍ Agent 路由（一次性判定）**

扫码或 H5 链接均带 KP 标识；首次进入会话按 KP 标识拉绑定 Agent 渲染形象 / 声音。

**规则与交互要点**

- slogan「有问题，就问 AI 问书」下方展示系统基于 KP 自动提炼的 3 条入门示例问题（点击即发送）；后续提问不再重判定。
- **知识库范围说明**：欢迎态首次展示一条「综合「XX」全部知识为你解答」，告知用户答案来自该机构全量知识库（发出首条消息后消失）。

**▍ 输入框能力开关（深度思考 / 智能搜索）**

会话输入框下方提供两个相互独立的能力开关。

**规则与交互要点**

- **深度思考**：开启后调用更强推理、给出更细致的思考型回答，**默认开启**。
- **智能搜索**：开启后允许联网检索补充知识库未覆盖信息并标注来源，**受机构「联网配置」总开关约束**（机构未开启联网时此开关不生效），**默认关闭**。
- 视觉状态：未选中＝白底 + 黑字 + 黑 icon；选中＝主题色（靛蓝软底 + 靛蓝字 / icon）；状态随会话保留。

**▍ 流式答案 + 多模态卡片**

文字打字机式流式输出，下方紧凑排布多模态媒体。

**规则与交互要点**

- 仅新生成的回答展示打字机动效；切换历史会话、实时电话挂断返回等场景，已生成回答直接整段展示、不重复动效。
- 卡片内**文字区在上、媒体区（图 / 音 / 视）在文字区下方**，两区做明显视觉区分；媒体支持左右滑动，**顺序按后台返回的相关度从左到右排列**（非图→音→视固定序）。
- 受限内容按权益打锁标；点击任一媒体可放大。
- **引用 KP 失效呈现**：媒体所属 KP 被下架时封面置灰 + 「已下架」角标，点击提示「该内容已下架，暂不可查看」（不进预览、不弹付费墙）；被删除（逻辑删除）时置灰 + 「已失效」角标，点击提示「该内容已失效，若有问题请联系客服」。溯源抽屉中引用失效 KP 的条目同样加灰标「已下架 / 已失效」、点击不跳转。

**▍ 答案操作（复制 / 点赞 / 反馈）**

每条 AI 答案打字完成后、「参考 N 篇知识」入口左侧并排展示复制、点赞、反馈三个 icon。

**规则与交互要点**

- 复制答案文本（toast「已复制答案」）；点赞（可取消、单选）；反馈（点踩）打开反馈 sheet。点赞 / 反馈 icon 为灰色系描边填充样式（选中态为灰色填充、非主题色）。
- **反馈 sheet**：4 个标签单选——「有害 / 不安全」「虚假信息」「没有帮助」「其他」+ 多行原因输入；提交 → toast「已记录反馈，感谢你的帮助」（该记录进入机构后台「答案反馈」工作台）。

**▍ 输入框语音输入**

麦克风按钮单击 / 长按进入语音输入态。

**规则与交互要点**

- 在当前会话页底部弹出音浪动画浮层（非全屏新页；浮层背底与会话背景自然过渡）；点击音浪外任意位置即关闭并发送本次语音问题、触发 AI 回答。

**▍ 回答溯源富信息**

答案下展示「参考 xx 篇知识」入口，点击后从右侧抽屉拉出溯源列表。

**规则与交互要点**

- 仅按相关度从高到低排序、**不展示相关度数值**（排序规则仅研发依据，界面不显示）。
- 分两块、中间浅灰横线分隔：上块为知识 KP（KP 封面 48×60 + KP 名称 + 文件名 + 章节页码；同一 KP 命中多文件归并、最多展示 2 个，其余「…等 N 个文件」），下块为互联网检索内容（站点用小圆形图标）。
- 条目点击：book 类型跳转该 KP 纸书购买链接，链接为空提示「暂不可查看详情」（3 秒消失，居屏幕中上方）；web 类型直接打开来源网页。

**▍ 媒体资源区与付费墙时机**

答案卡片内「相关媒体资源」作为加粗小标题直接贴在卡片上（不再单独灰底框）；受限媒体封面右上角按权益打标（会员 = 琥珀、永享 = 珊瑚红 + 单价）。

**规则与交互要点**

- 付费墙两种触发：① 在会话内直接点击需付费媒体 → 直接弹付费墙（不进放大预览）；② 进入放大预览后翻页到需付费内容 → 在放大预览界面下方弹付费墙（盖在预览之上）。
- **付费墙按门槛动态：永享内容**显「¥X 永久解锁此内容」（副文案「永享内容单独购买、永久持有，无需开通会员」）→ 经手机号门槛进收银台；**会员内容**显「开通会员 · 畅享全部会员内容」→ 进会员订阅页。
- 付费墙去除左侧锁图标，标题 / 描述 / 按钮整体居中。

**▍ 推荐追问**

展示在多模态卡片下方，2–3 个追问上下纵向堆叠（非左右并列），点击即发送。

**▍ 多模态全屏预览 + 版权保护**

放大后顶部固定「因版权限制，暂不支持保存下载」；底部缩略图条可点击切换，主预览区支持左右滑动浏览同卡片其他媒体。

**▍ 机构 Token 超额拦截**

当前机构 Token 已达上限时，会话页顶部常驻珊瑚红提示条「当前机构 Token 已达上限，请联系客服」。

**规则与交互要点**

- 拦截**所有发送入口**——文字发送、语音输入、点电话进实时通话均被拦下、问题不发出；再次触发时让顶部提示条放大抖动 + 跳亮提醒（不再弹 toast）。

**▍ 会话历史与新建会话**

顶栏菜单打开左侧历史抽屉，右上「+」新建会话。

**规则与交互要点**

- 历史抽屉：顶部「新建会话」+ 按时间分组的历史会话列表（点击载入该问答）+ 底部用户卡（头像 / 昵称 / 会员标 / 手机号，点击进「我的」；会员标随会员状态同「我的」页二分展示，**「0807 修订」**接同一数据源不再硬编码）。
- 跳去开会员 / 支付 / 实时电话再返回时仍回到**同一会话**（非新会话）；新建会话清空当前消息回到欢迎态。

**▍ 实时电话式语音**

**会员专属能力**：未开通会员点击电话入口时引导开通；开通后进入独立电话页。

**规则与交互要点**

- 中央 Agent 形象，下方居中「挂断」（返回原会话并定位最近一轮），左侧「静音」（关闭时不收音），右侧「字幕」（开启时显示字幕、Agent 形象隐藏）。
- 挂断按钮上方展示实时语音状态文案 + 动画（如「正在听…」「正在回答…」）。
- 字幕开启时对话文本按交互时序自上而下、左对齐排列，用户文本浅灰、AI 回复深黑；全程问答同步写入 AI 会话历史。

### 6.1.3 付费墙与权益

**▍ 开通会员（AI 会员订阅页）**

会员开通页，**两种购买方式互斥、无年付**；「购买方式即续费语义」，消除「按月自动续费」歧义；开通前过手机号门槛。

**规则与交互要点**

- **页面信息架构**：先「免费 vs 会员」权益对比 → 再两枚套餐卡 → 后协议勾选与开通按钮（先确认买到什么，再选怎么付钱）。整卡可点，选中态＝左侧对勾圆点（琥珀填充）+ 琥珀描边淡底。
- **连续包月**（默认选中，角标「首月特惠」）：卡名旁续费语义 pill「**自动续费 · 可随时取消**」，卡内说明「首月 ¥9.9（原价 ¥19.9），次月起 ¥19.9/月 自动续费；退订后当期仍可用至期满」。
- **（0812）月度周期按「对日周期」计算**：自开通当日顺延至次月同日；次月无对应日期则顺延至当月最后一日并固化（1 月 31 日开通 → 当期至 2 月 28 日，此后每月 28 日续费）。规则详见 4.4.5 ④。
- **单月会员**：卡名旁灰色 pill「**一次性购买 · 不自动续费**」，卡内说明「**¥19.9 / 1 个月，到期自动失效不扣款，适合先体验一个月**」。
- **协议与按钮随所选方式联动：连续包月→《会员服务协议》+《自动续费协议》两份 + 按钮「¥9.9 开通连续包月」；单月→**仅《会员服务协议》\*\*+ 按钮「¥19.9 购买单月会员」。协议勾选真实可点且**默认未勾选**（v1.10 合规修订：含《自动续费协议》的场景不做默认代勾），未勾选时开通按钮呈置灰视觉、点击 → 拦截并 toast「请先阅读并同意相关协议」，不进入收银台。
- **按钮下方无补充说明文案**——续费语义已由卡内 pill 与说明承载，不在页底重复（原两段页底说明已删除）。
- 点开通按钮 → 经**手机号门槛**校验 → 进微信支付收银台（amount 取所选方式）。

**▍ 会员中心**

会员态管理页（会员卡 + 免费 vs 会员权益对比 + 自动续费开关）。

**规则与交互要点**

- 会员卡：品牌标识 + 有效期 + 当前续费态（按月自动续费 / 到期不再续费）。

## 6.2 机构后台 Web PC（机构运营）

**▍ 父子机构数据范围（「0807 新增」，机构后台横切规则）**

概念：**父机构**＝本机构下辖 N 个机构；**子机构**＝有父机构的机构；**独立机构**＝无父无子。登录账号所属机构的类型由机构主数据父子关系决定（原型顶栏提供〔演示〕三态切换预览）。

**规则与交互要点**

- **父机构视角 · 六个业务页（知识产品 KP / Agent 人设 / C 端用户 / 订单管理 / 兑换码 / 答案反馈）**：筛选区新增「机构」**单选**下拉——选项＝全部机构（默认）/ 本机构（带「父机构」标）/ 各子机构，联动下方列表 / 卡片；列表 / 卡片展示**数据归属机构名称**。
- **（0812）无生效套餐空态**：机构无订阅或套餐全部过期时，订阅卡区分两态——全部过期＝卡头保留上一套餐名 +「已过期」标 + 「上一套餐「{套餐}」已于 {到期日} 到期：机构既有内容与数据完整保留，C 端问答与新建 / 上传暂停，续费后即时恢复」+ 引导「如需开通或续费，请联系平台客服」；从未开通＝「暂未开通订阅套餐」+ 开通价值说明 + 同引导。历史经营数据照常展示；平台用量看板同规则，且配额阈值预警条随之隐藏。页头〔演示〕「订阅状态」三态切换（正常 / 全部过期 / 未开通）。
- **父机构视角 · 主控台 / 数据看板**：新增「机构」**多选**筛选（选项＝本机构（父机构）＋全部子机构，默认全选、支持跨机构任意组合勾选），全部指标随所选机构集合联动——计数 / 金额类绝对量按集合聚合，率类指标按集合整体口径重算（非各机构简单相加）；导出沿用当前机构集合。
- **数据权限（与角色权限口径一致）**：机构后台角色的「可操作」权限**仅针对本机构数据**——父机构可见下属子机构数据（列表可筛、看板可汇总），但对子机构数据仅可查看、操作入口置灰并提示「仅可操作本机构数据」；平台后台角色的「可操作」权限可跨机构操作全平台数据。
- **子机构 / 独立机构视角**：界面与现状一致（无机构筛选、无归属列）；子机构在个人中心展示上级机构。
- **机构多选交互定稿（0807-2）**：选项行＝自绘勾选框（选中靛蓝底白勾）＋「（父机构）」靛蓝标；顶部「全部机构」快捷全选（分隔线隔开）；触发器回填所选机构名（全选＝「全部机构」、部分＝顿号拼接、超宽省略号）；至少保留一家。数据看板的机构多选位于页头「导出」左侧（与主控台同位）。
- **导出 Sheet 结构对齐页面栏目（0807-3 定稿）**：主控台＝当前订阅（本机构配额，不随机构筛选）/ 实时总览 / 经营分析；数据看板＝活跃概览 / 用户留存 / 区间分析（四个主题 Tab 合并为一个 Sheet、行首列标注 Tab 名）。父机构视角头部 scope 标「本机构（父机构）」＋筛选条件注明机构范围——导出数据随页面机构多选联动（多选＝合并口径、单选＝单机构），不单独产出分机构明细。
- **订阅套餐卡口径（0807-2）**：订阅是机构级合同（各机构各自签、配额上限不同、聚合无意义）——父机构视角固定显示本机构订阅与配额、不随机构多选联动，卡右上角灰字注明「本机构订阅 · 不随机构筛选变化」；子机构订阅在平台后台对应机构详情查看。

- 右侧「关联 KP」卡片：列出该 Agent 关联的 KP，点「前往 KP」跳转，仅查看不可在此编辑关联。

**规则与交互要点**

### 6.3.3 订阅订单（全域 · 机构管理组）

机构的"套餐 / 配额"由具有生命周期的「订阅订单」承载，替代直接手改额度，完整保留签约时间 / 套餐 / 商务负责人 / 有效期等历史，支撑营收、续费率与商务业绩统计。其与加油包、当前可用额度的关系见下图。

- **KP 数 / 存储已用**：机构当前实际占用，跨订阅连续；**Token 已用**：当前生效订阅周期内累计消耗，新订阅生效时清零重新统计。
- **额度替换**：新订阅生效时三项基础上限整体替换，不结转旧订阅剩余额度；加油包只在所属订阅周期内累加，到期不结转。
- **降配**：新上限低于 KP / 存储当前占用时，既有内容与权益保留，但阻断新建 KP、上传文件与独立快照导入，直至占用回落。
- **共享计量（0812 修订）**：实时同步**占消费机构 KP、不占**存储（文件实体在源机构）、消耗其 Token（原「不占 KP / 存储」作废）；独立快照占消费机构 KP / 存储、消耗其 Token。
- **无生效套餐空态（0812）**：机构无订阅或套餐全部过期时，当前生效订阅卡区分「全部过期」（保留上一套餐名与到期日 + 影响说明）与「从未开通」两态，平台侧引导「新建订阅」；预置演示机构「EE 美术出版」（全部过期）与「AA 少儿分社」（从未开通）。

**v1.4 图示替代说明**：旧订阅 / 加油包关系图因“已用”口径过期已移除；以本节蓝色规则为唯一研发和验收依据。

**▍ 订阅（常规）**

定套餐（新建订阅弹窗预设 6 档：体验 / 基础 / 专业 / 旗舰 / 定制 / 不限；选套餐带出 KP 数 / 存储 / Token 三项额度、可微调，改额度后自动匹配套餐、不命中则归「定制」，选「不限」三项不可输入）+ 有效期；新签 / 续签仅触发时机先后、不让用户手选。

**规则与交互要点**

- **生效规则（方案 A+C）**：① 同一时间段只能有一个生效订阅；② 有生效订阅时**最多再预建 1 期未生效订阅**（续约）；③ 新建有效期**不可与该机构已有订阅重叠**（重叠则拦截、不可创建）；④ 未生效订阅**到生效日期自动转生效**、无需手动。
- 故**无「状态」手动开关**——状态由有效期自动判定（起始日 > 今天 = 未生效；已覆盖今天 = 生效）；新建有效期默认从最晚订阅到期次日衔接一年（天然不重叠）。
- \*\*\*\*额度按计量性质分组标识（新建订阅 + 加油包）\*\*：KP 数、存储为「占用量」（随内容删除可释放，输入框旁标「占用」）；Token 为「消耗量」（只增不退、订阅周期结束清零重计，标「消耗」）；额度行附一行灰字说明，让填写人明确三个数值计算规则不同。

**▍ 订阅状态（三态、自动判定）**

订阅状态完全由有效期自动判定、无手动开关（原图 11 状态机因「已用」口径过期已于 v1.4 移除，以下列三态规则为唯一依据）。

**规则与交互要点**

- **未生效**：今天 < 生效日（预建的下一期续约，暂不计入当前可用额度）；到生效日自动转「生效」。
- **生效**：生效日 ≤ 今天 ≤ 到期日（决定机构当前可用额度，同机构同时仅一笔）。
- **已过期**：今天 > 到期日（历史已结束的服务周期）。

**▍ 订阅订单删除（带护栏放开）**

为处理"创建错了"与期中纠错，订阅订单操作列提供「删除」；删除条件由"零用量才可删"放开为按状态分级的带护栏规则：

- **① 未生效订单**：可直接删除（常规二次确认）。
- **② 已生效订单**：可删除，确认弹窗列明后果——连带删除其全部加油包、机构立即失去该订阅配额；若 KP / 存储 / Token 任一用量 >0，追加红色强警告「该订阅已产生用量，删除将立即中断机构服务」。
- **③ 已过期订单**：不可删除（商业单据审计留存，操作列不出删除入口）。
- **删除≠退款**：删除只移除订阅记录与配额，不产生退款单；如涉退费走线下商务流程。

**v1.4 状态机说明**：订阅状态仍由有效期自动判定；额度已用与删除校验必须分别读取机构当前 KP / 存储占用及当前订阅周期 Token 消耗，不再沿用旧图的按订阅拆分口径。

**▍ 加油包（期中加量）**

挂在某条订阅之下（parentId），即时生效、只在该订阅周期累加，不改变套餐；有效期跟随该订阅到期日且不结转下一订阅。

**规则与交互要点**

- 订阅记录 / 订阅订单的操作列「加油包」按钮 → 右抽屉展示该订阅的加油包列表（创建时间 / 创建人 / 加油包额度 / 备注 / 状态）并可直接新建；三项加量额度（KP / 存储 / Token）全为 0 不可创建并提示。

**▍ 当前可用额度（总额度，含加油包）**

上限 = 当前【生效】订阅基础额度 ＋ 该订阅下【生效】加油包；已用值按 KP / 存储当前占用与 Token 当前订阅周期消耗分别统计。

**规则与交互要点**

- 机构详情、用量看板与全域订阅订单必须在 InfoDot 中同时说明上限构成、已用周期、替换不结转及降配阻断。

**▍ 机构详情 · 订阅 / 配额 Tab**

- **订阅列表筛选**：商务负责人由下拉改为模糊搜索输入框，置于套餐筛选之前；其后依次为套餐、状态筛选。

**▍ 角色权限（机构 / 平台双类型）**

**规则与交互要点**

- 顶部分段切换「机构角色 / 平台角色」；左侧角色列表 +「新建角色」，右侧按菜单分组的权限点（每点三态切换）+ 保存。**三态图例**：无 = 看不见该菜单；只读 = 可进入查看、不能编辑 / 操作；可操作 = 全部操作可用。**「0807 明确」「可操作」数据范围口径**：平台角色的「可操作」＝可跨机构操作全平台数据；机构角色的「可操作」＝**仅针对本机构数据**——父机构账户虽可见下属子机构数据（列表可筛、看板可汇总，见 6.2「父子机构数据范围」），但对子机构数据仅可查看、不可操作（操作入口置灰并提示「仅可操作本机构数据」）；三态图例 InfoDot 同步补充本条说明。
- **机构角色（只读 / 客服 / 运营 / 机构管理员）权限点与机构后台菜单一致。其中「人设风格-自定义」（0812 由「Agent 回答 Prompt 编辑」更名为「Agent 人设风格编辑」、0812-e 再定名，权限 key agent.prompt.edit 始终不变）不是独立并列的权限点，而是「Agent 人设」的嵌套子项**——仅当「Agent 人设」= 可操作时才展开显示（无 / 只读时不显示，降级自动收起），用**缩进 + 灰色虚线连接线表达从属关系；机构管理员默认无此权限（内置角色中该权限点由平台超管统一开关）。「产品中心」组布局为知识产品 KP（左列）与 Agent 人设（右列）同行两列，Prompt 子项挂在右列 Agent 人设之下。平台角色**（平台财务 / 平台运营 / 平台超级管理员）权限点与平台菜单一致。权限点分组与侧栏菜单分组一一对应（如「角色权限」点归「系统设置」组）。
- 新建角色：角色类型继承当前“机构角色 / 平台角色”Tab并禁用不可切换；仅填写名称 + 备注，同类型不可重名；创建后权限置空、逐项设置。
- **功能权限标识：**「人设风格-自定义」为功能权限（其余均为菜单权限），在原位置就地加「功能权限」标签予以区分。
- **功能权限两态**：该权限由三态改两态（只读 / 可操作）——功能权限的「无」与「只读」语义相同（都表现为不可编辑），合并为「只读」；存量「无」视为「只读」。三态图例补充「功能权限＝不可编辑」说明。
- **新建角色弹窗精修**：弹窗加宽使角色类型一行完整展示；删除解释文案「由创建入口页签决定，不可切换」（置灰锁定态已自说明）。

**▍ 默认 LLM**

**规则与交互要点**

机构停用：「机构服务已暂停，如需恢复请联系管理员」；账户停用：「账户服务已暂停…」；无权限 / 页面不存在引导返回；前台二维码失效弹窗提示 3 秒跳首页。

**▍ 后台下拉选择器（两端通用）**

统一下拉框宽度为与同表单其他控件一致；选中后回显文字不使用主题色、与普通 UI 文本色一致（仅反映数据变化）。

**▍ 后台侧栏收起态（两端通用）**

左侧菜单收起后，鼠标悬浮浮出的菜单名小面板层级修正，不再被右侧表单内容遮盖。

# 第 7 章　数据指标与计算规则

本章逐一说明三端看板指标的**定义、统计口径、计算公式与示例**；示例用于说明计算方法，非真实经营数据。

## 7.1 通用计算口径

- **去重统计**：严格按指标指定主键做精确 DISTINCT，不使用经验系数估算。
- **「0724 新增」去重规则总述（两分类、全量落 tooltip）：**① 规模指标按用户去重——区间内按用户 ID 精确去重，同一用户多天活跃只算 1 人（适用：活跃用户、新增 C 端、付费用户、提问用户等）；② 强度指标按人天——用户 × 自然日（适用：日均活跃 DAU 均值、人均提问等）。例：张三在 7 天区间内第 1、2 天活跃、第 3 天起未来——「活跃用户」计 1、「日均活跃」贡献 2 个人天。展示规范：两后台所有涉及去重的指标，tooltip 面板内去重规则独立成一条无序项、格式统一为「· 去重：xxxx」，不再混在定义句里；功能清单「数据看板指标」「用量看板指标」两张附表单独增加「去重规则」列、逐指标标注。
- **「0724 新增」会员三分口径（三者互斥）：**新增会员＝区间内历史首次开通会员（续费、回流均不计入）；续费＝区间内到期且完成续费（续费率 = 区间内到期且完成续费的会员数 ÷ 同区间到期会员数）；回流＝区间内开通会员、且开通时会员状态为已过期（不算新增、不算续费）。任一次开通行为只落入其中一类。
- **指标三分类（决定看板分区）**：① **实时快照**——累计 / 存量（如累计 GMV、当前会员、KP 占用），截至当前、不随区间、不环比，含活跃概览 DAU / WAU / MAU（「0724 新增」定稿为固定滚动窗口快照，见下条）；② **区间统计**——随今日 / 7 日 / 30 日 / 自定义联动并与上一等长区间环比；③ **成熟 cohort**——留存率，按注册批次独立队列口径、不跟随全局区间筛选。各看板据此把 ① 归「实时」分区、② 归「区间 / 经营分析」分区、③ 用独立注册批次筛选，视觉上明确区隔。
- **「0724 新增」活跃指标（DAU / WAU / MAU）定稿为固定滚动窗口快照，不随区间筛选联动：**日活＝今日 00:00 至当前时刻的去重活跃（实时），环比昨日同时段；周活＝截至今日的近 7 日滚动窗口去重活跃，环比上一个 7 日窗口；月活＝截至今日的近 30 日滚动窗口去重活跃，环比上一个 30 日窗口。原因：区间筛选回答「这段时间表现如何」，而 WAU / MAU 定义自带固定窗口，两者绑定语义无法自洽——选「近 7 天」时 WAU 恰好等于区间去重活跃（重复指标），选 30 天 / 自定义时「对应的 7 日窗口」取哪一段没有唯一答案。三卡位于数据看板页面顶部「活跃概览」区块（用户留存上方、区间分析之外）；区间维度的活跃规模看「活跃用户（区间去重）」。此前「随区间联动」口径废止。
- **累计 / 快照**：截至当前时刻或区间末日存量，不随区间筛选、不展示上一周期比较。
- **今日**：本地时区 00:00 至当前时刻，对比昨日 00:00 至相同经过时长；趋势按小时。
- **近7天 / 近30天 / 自定义**：含首尾日期；对比紧邻的上一等长区间；趋势按日。
- **差值单位**：计数 / 金额显示相对百分比；率类为绝对差（百分点语义）、统一以「%」符号展示（**「0807 修订」**原「N 个百分点」文案改为「N%」、与计数类视觉一致，差值口径在指标 tooltip 注明）；时长显示绝对时长差。上一周期为0时显示“上期为0，暂无可比增幅”。
- **指标 tooltip**：每个指标必须写明定义、分子 / 分母、去重键、时区、统计周期、上一周期、差值单位与零基线规则。**「0724 新增」**涉及去重的指标，去重规则在 tooltip 内独立成一条无序项（「· 去重：xxxx」）。
- **GMV（成交总额）口径**：仅统计已支付订单的实付金额，含会员 + 永享；**兑换码订单金额计 0、不计入 GMV**。资金进入机构账户。**「0724 新增」**四态口径下待支付、已失效订单不计入；GMV、付费用户等营收指标仅计「已支付」订单，相关指标 tooltip 注明。
- **区间活跃用户**：按机构内 C 端 user_id 在指定区间精确去重；删除 0.62 / 0.42 系数。

**单位说明：**两后台数值统一采用中文万 / 亿进制（< 1 万用千分位、1 万\~1 亿记「X.X 万」、≥ 1 亿记「X.XX 亿」）；**Token 以「亿」为基准单位**（与机构配额 Token 口径一致），不再使用英文 M / k。各看板页脚附统一单位规范说明。

## 7.7 配额阈值短信预警（机构联系人）

机构本计费周期 Token 用量逼近上限时，自动向机构联系人发送短信预警，并在用量看板顶部显示预警条。

- **触发阈值（四档）**：本订阅周期 Token 消耗率达 **70% / 80% / 90% / 95%**，每档**首次达到时各发一次**短信；同一计费周期内同一阈值**不重复**推送；进入下一计费周期归零重置。
- **接收对象**：机构联系人手机号（在机构详情 · 基本资料维护）。
- **看板预警条**：用量看板顶部「本订阅周期 Token 已消耗 XX%」预警条**仅当 ≥ 70% 时出现并常驻**，< 70% 不显示；条内标注已发 / 待发阈值（如「已发 70% / 80%，达 90% / 95% 将再次提醒」）。
- **超限处理（闭环）**：Token / KP 数 / 存储超上限时——机构后台新建 KP / 上传超限 → 阻断并提示「请联系平台扩容」；前台 C 端提问 / 语音 / 实时入口被拦截、问题不发出，顶部珊瑚红提示条放大抖动「当前机构 Token 已达上限，请联系客服」。

**预警短信文案模版（四档共用一条参数化模版）**：签名用平台方「【AI问书】」（区别于 C 端验证码短信用机构名作签名）；\${orgName}＝机构名，\${pct}＝当前 Token 消耗率（70 / 80 / 90 / 95）；同一计费周期内每档仅首次达到时发一次。

【AI问书】您的机构「\${orgName}」本订阅周期 Token 用量已达 \${pct}%，达上限后 C 端问答将被暂停，请及时登录机构后台「订阅配额」扩容或联系客服。如已处理请忽略本短信。

## 7.8 列表导出规则（两后台通用）

两后台所有列表「导出」按钮遵循统一标准：

- **格式**：Excel（.xlsx）。
- **范围**：当前**筛选 + 排序后的全部结果**（非仅当前页，也非无视筛选的全量）。
- **字段**：列表可见列 + 必要的完整字段（完整订单号 / ID、精确到秒的时间、用户标识等，不脱敏截断）。
- **条数上限（拦截式，不下载）**：单次导出**任一业务 Sheet 数据行超 10000 条即拦截**——按各 Sheet 的最大行数判定（非全部 Sheet 累加），不生成文件、不触发下载，弹窗提示「请缩小筛选范围（如收窄时间区间或增加筛选条件）后重试，或**联系平台管理员导出完整数据**」。规则集中在导出底座（buildWorkbook / exportWorkbook）内拦截，两后台全部 16 处导出入口一致生效，无需逐个改。
- **文件名**：统一「AI问书\_{机构名｜全域}\_{业务名}数据导出.xlsx」，如 AI问书_XX出版社_订单管理数据导出.xlsx、AI问书_全域订单数据导出.xlsx。**筛选摘要与导出时刻不进文件名**，一律在每个 Sheet 头部信息行体现（标题 / 导出时间 / 全部筛选条件；实时指标另标实时统计时间，区间指标标注区间起止）——文件名保持稳定可预期，便于归档比对。
- **生成方式**：前端即时生成下载，不经审批流。
- **视觉**：首行标题、次行统计时间 / 筛选摘要；表头统一深靛蓝底白字，冻结表头并开启筛选。按内容设置列宽，短字段完整展示，长文本自动换行并顶端对齐，数据行使用浅色斑马纹。

# 第 8 章　埋点事件与数据采集

## 8.1 埋点事件清单

第 7 章的各项指标依赖前端埋点采集用户行为。前端需在关键事件点接入**第三方数据采集 SDK**（H5 以 JS SDK 方式接入），将事件上报到分析平台，用于还原漏斗、留存、转化等分析。下表为建议采集的核心事件。

| **事件名** | **触发时机** | **上报字段（payload）** | **说明** |
|-|-|-|-|
| login_wechat_start | 微信授权开始 | 无 | 进入微信授权过场 |
| login_wechat_done | 微信授权完成 | 无 | 授权回调成功 |
| phone_bind_submit | 手机号绑定提交 | 手机号 phone | 提交手机号 + 验证码 |
| chat_msg_submit | 提问提交 | 输入类型 input_type、字数 length | 发起一次提问（文字 / 语音） |
| chat_msg_done | 回答流式完成 | 回答字数 len | 回答生成结束 |
| chat_msg_cancel | 用户停止生成 | 无 | 点击「停止生成」 |
| asr_start | 语音转写开始 | 录音时长 duration_sec | 语音输入录制时长 |
| asr_done | 语音转写完成 | 无 | 转写文本返回 |
| paywall_pay_start | 支付发起 | 订单类型 type、金额 amount、KP 标识 kpId | 收银台拉起 |
| pay_success | 支付成功 | 订单类型 order_type、金额 amount | 创建订单并发放权益 |
| pay_cancel | 支付取消 | 订单类型 order_type | 用户取消支付 |
| pay_fail | 支付失败 | 订单类型 order_type | 支付失败 |
| redeem_attempt | 兑换码尝试 | 兑换码 code | 提交兑换码 |
| redeem_fail | 兑换码失败 | 失败原因 reason（格式错误 / 已使用） | 兑换码校验失败 |
| qr_scan（建议补充） | 扫码进入 | 二维码 ID qr_id、KP 标识 kpId | 还原「扫码 → 付费」漏斗源头 |
| paywall_show（建议补充） | 付费墙曝光 | 类型 type、KP 标识 kpId | 对应「受限内容触发率」 |

结合 qr_scan（扫码进入）与 paywall_show（付费墙曝光），可完整还原「扫码 → 提问 → 付费墙曝光 → 发起支付 → 支付成功」核心转化漏斗，与第 7 章「会员漏斗 / 受限内容触发率」指标一一对应。
